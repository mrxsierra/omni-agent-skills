# ⚔️ Technical Competitive Intelligence & Moats Framework

The **Technical Competitive Intelligence** skill provides a structured methodology for performing objective technical comparisons, evaluating architectural moats, and drafting transparent "Why Not X?" documentation.

## 1. Inputs & Context Required
- **Target Project:** Architectural specifications, capabilities, dependencies, and design goals.
- **Comparison Cohort:** Related tools, libraries, or protocols operating within the same problem space.
- **Evaluation Dimensions:** Technical dimensions (e.g. bundle size, execution model, runtime dependencies, license, performance trade-offs).

## 2. Step-by-Step Procedure
1. **Dimension Definition:** Establish objective, reproducible criteria for comparison (e.g. zero-dependency portability vs framework integration).
2. **Feature & Architecture Matrix:** Map out feature support, architectural design choices, and system trade-offs in a side-by-side comparison table.
3. **Trade-Off & Non-Goal Articulation:** Identify specific scenarios where alternative solutions are superior or better fit.
4. **"Why Not X?" Documentation:** Draft concise, respectful explanations of why architectural choices were made and how the project differs from established tools.
5. **Review & Factual Grounding:** Verify all claims against official documentation or reproducible benchmarks of the compared tools.

## 3. Expected Outputs & Artifacts
- **Technical Comparison Matrix:** Markdown table contrasting architecture and trade-offs.
- **"Why Not X?" Guide:** Clear documentation section explaining design trade-offs.

## 4. Constraints & Tool Neutrality
- **Factual & Respectful:** Base comparisons on verified documentation and observable facts without marketing disparagement.
- **Evidence-Grounded:** Never make unsubstantiated performance claims without reproducible test code.
- **Tool Neutral:** Methodology applies across software architectures, protocols, and language ecosystems.
